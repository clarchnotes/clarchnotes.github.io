# GPU基本概念：从零开始理解GPU并行计算

## 第一部分：宏观视角 —— 为何选择GPU进行计算？

### 1. GPU并行计算导论

#### 什么是GPU？

图形处理器（GPU）最初设计用于高效处理计算机图形渲染任务，例如在视频游戏中创建复杂的视觉效果。然而，研究人员和工程师很快意识到GPU的大规模并行处理能力不仅限于图形，还可以应用于各种计算密集型领域。因此，通用GPU（GPGPU）的概念应运而生，使得GPU成为科学计算、数据分析、人工智能等领域的重要工具。

#### 为何使用GPU进行计算？大规模并行的需求

许多复杂的科学和工程问题本质上是高度并行的，意味着它们可以被分解成大量可以同时独立或半独立执行的小任务。传统的CPU（中央处理器）虽然单个核心功能强大，但在并行处理任务数量上有限。GPU通过拥有数百甚至数千个相对简单的计算核心，能够同时执行海量计算任务，从而在处理这类问题时展现出远超CPU的性能，即实现高吞吐量（High Throughput）。

#### GPU与CPU对比：核心设计理念与目标负载

CPU和GPU的设计目标有着根本的不同：

| **特性** | **CPU (中央处理器)**      | **GPU (图形处理器)**         |
| ------ | -------------------- | ----------------------- |
| 核心数量   | 少量（通常4-64个）          | 大量（数百到数千个）              |
| 核心设计   | 复杂，支持乱序执行，强大的控制逻辑    | 相对简单，更多晶体管用于计算单元        |
| 缓存大小   | 大（MB级别，多级缓存）         | 较小（KB级别，但有特殊的共享内存和纹理缓存） |
| 优化目标   | 低延迟（单个任务快速完成）        | 高吞吐量（单位时间完成更多任务）        |
| 分支预测   | 先进且复杂                | 有限，更倾向于一致的执行路径          |
| 指令流    | 多样化，适合复杂的控制流（MIMD趋势） | 统一（SIMT模型是主流）           |
| 主要任务   | 通用计算，操作系统，复杂逻辑，串行任务  | 大规模并行计算，如图形渲染，科学计算，AI   |

这种设计差异使GPU特别适合于可以分解为大量相似计算的数据并行任务，如矩阵运算、图像处理、深度学习模型的训练与推理等。

### 2. CUDA简介

#### 什么是CUDA？

CUDA (Compute Unified Device Architecture，计算统一设备架构) 是由NVIDIA推出的并行计算平台和编程模型。它允许软件开发者和软件工程师使用NVIDIA GPU进行通用目的处理 (GPGPU)。CUDA平台提供了一套完整的开发工具，包括编译器、库和API，支持使用C、C++、Fortran等高级编程语言编写可在GPU上执行的程序。

#### 内核函数（Kernel Function）的概念

在CUDA编程中，**内核函数 (Kernel Function)** 是在GPU上并行执行的函数。当一个内核函数从CPU（主机端 Host）启动时，它会在GPU（设备端 Device）上由成千上万个线程并行执行。开发者通过定义内核函数的行为来指定每个线程需要完成的工作。

### 3. CUDA编程模型：并行层次结构

CUDA编程模型的核心在于其如何组织和管理并行执行的线程。这种层次结构使得开发者能够有效地将计算任务映射到GPU的并行硬件上。

![](attachments/Pasted%20image%2020250510231736.png)
#### 线程（Thread）

线程是CUDA编程模型中的**基本执行单元**，是最小的计算单位。

**详细特性**：

- 执行单个指令序列。
- 每个线程有唯一的线程ID（`threadIdx`），可用于确定其处理的数据。这个ID通常是一维、二维或三维的，方便映射到多维数据。
- 拥有私有寄存器状态和私有内存（局部内存）。
- 线程执行由编译器从CUDA C/C++转换而来的SASS（Streaming ASSembler）或PTX（Parallel Thread eXecution）代码。
- 相比CPU线程，GPU线程更轻量级，上下文切换开销极低。
- 理论上可以有独立的指令指针/程序计数器，但出于SIMT模型的性能考虑，通常线程束（Warp）内的线程共享同一指令指针。

在CUDA核函数中，可以通过内置变量获取线程在其线程块内的索引：

```
// 在核函数中获取线程索引 (通常threadIdx.x用于一维，(threadIdx.x, threadIdx.y)用于二维等)
int tx = threadIdx.x;
int ty = threadIdx.y;
int tz = threadIdx.z;
```

#### 线程块（Block / Thread Block / 协作线程阵列 CTA）

线程块是**一组线程的集合**。同一线程块内的线程被组织在一起，可以相互协作。在硬件实现上，线程块也被称为协作线程阵列(CTA - Cooperative Thread Array)。

**详细特性**：

- 一个线程块可以包含多个线程（例如，最多1024个线程，具体限制取决于GPU的计算能力）。
- **协作**：
    - **共享内存 (Shared Memory)**：块内线程可以通过高速的片上共享内存交换数据。
    - **同步 (Synchronization)**：块内线程可以使用同步原语（如 `__syncthreads()`）进行同步，确保某些操作在所有块内线程都到达某个点之后才继续执行。
- 线程块可以组织成一维、二维或三维的结构，由内置变量 `blockDim`（`blockDim.x`, `blockDim.y`, `blockDim.z`）指定块的维度。
- 每个线程块在网格中也有一个唯一的ID，称为 `blockIdx`（`blockIdx.x`, `blockIdx.y`, `blockIdx.z`）。
- 一个线程块会被完整地调度到**单个流多处理器 (SM)** 上执行，并且一旦分配，就会在该SM上执行直到完成。块之间通常不能直接进行高效同步（除非使用全局原子操作或特定的高级同步原语）。
- 选择合适的块大小（通常是线程束大小32的倍数）对于性能至关重要，以避免部分填充的线程束。

**线程块标识与全局线程ID计算示例 (一维)**：

```
// 线程块内的线程ID
int tid_in_block = threadIdx.x;

// 线程块在网格中的ID (假设为一维网格和一维线程块)
int block_id = blockIdx.x;

// 线程块的维度 (每块有多少线程)
int threads_per_block = blockDim.x;

// 计算全局线程ID
int global_tid = block_id * threads_per_block + tid_in_block;
```

#### 网格（Grid）

网格是**一组线程块的集合**。当你从CPU调用一个CUDA内核函数时，你实际上是在启动一个网格。

**详细特性**：

- 一个网格可以包含非常多的线程块，从而使得数百万个线程能够并行执行，覆盖整个计算任务。
- 网格也可以组织成一维、二维或三维的结构，由内置变量 `gridDim`（`gridDim.x`, `gridDim.y`, `gridDim.z`）指定网格的维度。
- 网格的维度通常根据输入数据的大小和希望的并行粒度来决定。

内核启动语法：

在CUDA C/C++中，使用三个尖括号 <<< >>> 语法来配置网格和块的维度并启动内核函数：

```
// 定义线程块和网格维度
dim3 blockDim(16, 16);  // 每个块包含16×16=256个线程 (假设为2D块)
dim3 gridDim((width + blockDim.x - 1) / blockDim.x,
             (height + blockDim.y - 1) / blockDim.y); // 根据数据大小计算网格维度 (假设为2D网格)

// 启动内核
myKernel<<<gridDim, blockDim>>>(/* kernel arguments */);
```

这里的 `(width + blockDim.x - 1) / blockDim.x` 是一种常用的向上取整方法，确保有足够的线程块来处理所有数据。

#### 线程束（Warp）

线程束是GPU硬件执行线程的**基本调度和执行单位**。它是一组**固定数量（目前所有NVIDIA GPU上都是32个）的线程**。

**详细特性**：

- 虽然开发者以线程和线程块的逻辑结构组织代码，但SM实际上是以线程束为单位来管理和执行这些线程的。
- **SIMT (Single Instruction, Multiple Thread) 执行**：同一个Warp中的32个线程同时（或在概念上同时）执行相同的指令。每个线程有自己的寄存器和数据，因此可以对不同的数据执行相同的操作。
- **线程分化 (Thread Divergence)**：如果一个Warp中的线程遇到条件分支（如 `if-else` 语句），并且线程走向了不同的分支路径，Warp会依次执行每个分支路径。在该Warp执行某个特定分支路径时，只有走向该路径的线程是激活的，其他线程则处于禁用（masked out）状态。这会降低执行效率，因为不是所有32个线程都在同时做有用的工作。因此，在CUDA编程中，应尽量避免或减少Warp内的分支分化。
- **线程束同步**：
    - 同一Warp内的线程在执行指令时具有隐式的同步性。
    - CUDA提供了线程束级别的同步原语（如 `__syncwarp()`，或`_sync()`后缀的warp内shuffle、vote等指令），允许Warp内的线程进行更细粒度的同步和数据交换，而无需等待整个线程块。
- 线程束的形成和调度对CUDA编程者来说通常是透明的，由硬件自动管理。但理解Warp的行为对于编写高性能CUDA代码至关重要，尤其是在内存访问和分支控制方面。

## 第三部分：深入探索 —— GPU架构揭秘

### 4. 关键GPU硬件组件

#### 流多处理器（Streaming Multiprocessor, SM）：执行的核心引擎

SM是NVIDIA GPU的主要计算单元，是执行CUDA内核的核心。可以将SM看作GPU内部的一个小型并行处理器。

**作用**：

- 一个或多个线程块会被调度到单个SM上执行。
- SM负责管理、调度和执行其上驻留的线程块中的线程束（Warps）。

SM内部关键组件：

SM是一个复杂的单元，集成了多种执行资源和内存：

- **CUDA核心 (CUDA Cores)**：执行实际的算术和逻辑运算。
- **线程束调度器 (Warp Schedulers)**：选择就绪的Warp并分发指令。
- **分发单元 (Dispatch Units)**：将指令发送给执行单元。
- **寄存器文件 (Register File)**：供线程存储私有数据，数量庞大。
- **L1缓存/共享内存 (L1 Cache / Shared Memory)**：一块可配置的高速片上内存，一部分用作L1数据缓存，另一部分用作线程块内线程共享的内存。
- **特殊功能单元 (SFUs)**：用于执行超越函数（如sin, cos, sqrt, rsqrt, log, exp）。
- **加载/存储单元 (LSUs)**：负责处理对内存（如全局内存）的读写请求。
- **张量核心 (Tensor Cores)** (在支持的架构中)：专门用于加速深度学习中常见的矩阵乘加运算。

资源分配：

SM是资源分配的基本单位。一个SM可以同时处理多个线程块，只要SM上的可用资源（如寄存器数量、共享内存大小、最大线程数/块数限制）能够满足这些线程块的需求。这些资源在分配给线程块后，由块内的线程共享或分配给线程。

#### CUDA核心（CUDA Core）

CUDA核心是NVIDIA GPU的基本计算单元，主要负责执行浮点数和整数算术指令。

**详细特性**：

- 执行标量算术指令，如加法、乘法、乘加等。
- 每个CUDA核心通常包含一个整数算术逻辑单元 (ALU) 和一个浮点单元 (FPU)。
- 不同GPU架构的CUDA核心设计和能力可能有所不同，例如支持的精度（FP32, FP64, INT32等）和每周期指令数。
- **与CPU核心的区别**：CPU核心是设计用来独立执行复杂指令序列的，拥有复杂的控制逻辑、分支预测、乱序执行等。而CUDA核心更为简单，专注于高吞吐量的算术运算，并且不是独立调度的，而是作为SM内Warp的一部分被调度。
- 例如，NVIDIA H100 GPU的每个SM包含128个主要用于FP32运算的CUDA核心，但对于32位整数或64位浮点运算，可能只有部分核心（如64个）能够同时执行。

#### 张量核心（Tensor Core）

张量核心是NVIDIA从Volta架构开始引入的专用硬件单元，旨在显著加速深度学习训练和推理中常见的矩阵乘加（Matrix Multiply-Accumulate, MMA）运算，即 $D=A\times B+C$。

**详细特性**：

- 一次操作可以处理一个小型的矩阵块（例如4x4或8x8，取决于架构和精度）。
- 相比CUDA核心，SM内的张量核心数量较少，但每个张量核心的计算能力（尤其对于特定矩阵运算）非常强大。
- 支持多种数据精度，包括FP16（半精度浮点）、BF16（BFloat16）、TF32（TensorFloat-32，Ampere架构引入）、FP64（双精度，部分高端计算卡支持）以及INT8、INT4等整数类型，以平衡性能和精度需求。
- 例如，Hopper架构的第四代张量核心，在使用FP8精度时，其理论峰值运算能力非常惊人。

**应用场景**：

- 深度学习模型的训练和推理（卷积层、全连接层等）。
- 高性能计算（HPC）中涉及大规模矩阵运算的领域。
- 计算机视觉和自然语言处理中的某些算法。

#### 特殊功能单元（SFU - Special Function Unit）

特殊功能单元（SFU）负责执行比基本加法和乘法更复杂的单操作数数学运算。

**功能**：

- 计算超越函数，如正弦 (sin)、余弦 (cos)、指数 (exp)、对数 (log)、平方根倒数 (rsqrt)、平方根 (sqrt) 等。
- 每个SM通常包含多个SFU（例如，一个SM可能有4个SFU）。
- 这些函数的执行通常需要比简单算术运算更多的时钟周期。

#### 加载/存储单元（LSU - Load/Store Unit）

加载/存储单元（LSU）负责处理GPU核心与各级内存（如全局内存、共享内存、L1缓存）之间的数据传输请求。

**特性**：

- 执行从内存加载数据到寄存器，或从寄存器存储数据到内存的指令。
- 支持合并内存访问（Coalesced Memory Access）：当一个Warp中的线程访问连续的内存地址时，LSU可以将这些访问合并成更少、更高效的内存事务，从而提高内存带宽利用率。
- 对内存访问模式高度敏感。非合并的、随机的内存访问会导致性能显著下降。

### 5. GPU架构演进与计算能力（Compute Capability）

NVIDIA GPU架构随着时间的推移不断演进，每一代新架构都会带来性能提升、能效改进以及新的硬件功能。

**主要架构世代示例**：

1. **Tesla** (2006-2010)：首个统一着色器架构，为GPGPU奠定了基础。
2. **Fermi** (2010)：首个真正意义上为计算设计的架构，引入了L1/L2缓存层次、ECC内存支持等。
3. **Kepler** (2012)：提升了SM（称为SMX）的设计，引入动态并行（Dynamic Parallelism）、Hyper-Q技术。
4. **Maxwell** (2014)：显著提升能效，改进调度器。
5. **Pascal** (2016)：引入NVLink高速互联技术，支持HBM2内存，原生支持FP16（半精度）计算。
6. **Volta** (2017)：引入张量核心（Tensor Cores），支持独立线程调度。
7. **Turing** (2018)：在消费级市场引入RT核心（用于光线追踪加速）和增强的张量核心。
8. **Ampere** (2020)：第二代RT核心，第三代张量核心（支持TF32、BF16等更多精度），更大的L2缓存，SM设计进一步优化。
9. **Hopper** (2022, 数据中心架构)：第四代张量核心，引入Transformer引擎，支持FP8精度，显著提升AI和HPC性能。
10. **Ada Lovelace** (2022, 消费级架构)：改进的光线追踪性能，DLSS 3.0，SM优化。

**计算能力 (Compute Capability, CC)**：

- 计算能力是一个版本号（如7.5, 8.6, 9.0），用于标识NVIDIA GPU的硬件架构特性和支持的CUDA功能集。
- 它由一个主版本号和一个次版本号组成。主版本号通常代表一个主要的架构系列（例如，CC 8.x 对应Ampere架构，CC 9.x 对应Hopper架构）。次版本号表示该主架构系列内的增量改进或特性差异。
- 开发者需要根据目标GPU的计算能力来编译CUDA代码，以确保使用了GPU支持的功能，并可能针对特定架构进行优化。较新的计算能力通常意味着更强的性能和更多的特性（如新的指令、更大的共享内存、更多的寄存器等）。
- 注意：有时主版本号可能跨越一个以上的架构名称，或者一个架构名称下可能有略微不同的计算能力版本（例如Ada Lovelace架构的消费级GPU计算能力为8.9，虽然主版本号与Ampere的8.x系列相同，但特性有所不同）。

## 第四部分：协同工作原理 —— 执行与内存

### 6. 内核执行流程与调度

#### 网格/线程块到SM的映射

当一个内核函数启动时，其对应的线程块网格（Grid of Thread Blocks）会被GPU的硬件调度器分配到可用的流多处理器（SMs）上。

- 一个线程块（Block/CTA）总是被完整地分配给**一个**SM执行，并且在该SM上运行直至完成。
- 一个SM可以同时执行一个或多个线程块，这取决于SM的资源（如寄存器、共享内存、最大线程数）以及每个线程块的资源需求。这种并发执行多个线程块的能力称为SM的**占用率（Occupancy）**。

#### 线程束调度器（Warp Scheduler）与延迟隐藏

SM内部包含一个或多个线程束调度器（Warp Scheduler）。

详细功能：

- 每个SM通常有多个（例如4个在现代GPU中）线程束调度器。
- 线程束调度器负责从当前分配给该SM的线程块中，选择就绪（Ready) 的线程束（Warps）并将其指令分发到SM的执行单元（如CUDA核心、SFU、Tensor Core）。一个线程束是就绪的，意味着它的下一条指令的操作数已经准备好，并且执行单元也可用。
- **延迟隐藏（Latency Hiding）**：这是GPU实现高吞吐量的关键机制。当一个Warp执行一条长延迟指令时（例如，从全局内存加载数据，这可能需要数百个时钟周期），它会暂停执行并等待数据返回。此时，线程束调度器并不会让SM空闲，而是会**立即切换**到另一个就绪的Warp并执行其指令。由于一个SM上通常驻留着许多Warp（来自一个或多个线程块），调度器总能找到可执行的Warp。这种快速的、几乎零开销的Warp上下文切换有效地隐藏了内存访问和其他长延迟操作的延迟，使得计算单元能够持续保持繁忙。
- 调度器使用**记分板（Scoreboarding)** 或类似的机制来跟踪指令的操作数依赖关系，以确保只有当操作数可用时才分发指令。

#### SIMT执行模型（硬件视角）

单指令多线程（SIMT）是GPU的基本执行模型。

详细特性：

- 在硬件层面，一个Warp（32个线程）在任何给定时刻都执行相同的指令。
- SM的执行单元是按照Warp为单位进行操作的。
- 每个线程在Warp内有自己的程序计数器（逻辑上）和私有数据（寄存器），因此虽然指令相同，但每个线程可以在不同的数据上操作。
- **执行掩码（Execution Mask）**：当Warp遇到分支（如`if-else`）且线程走向不同路径时（线程分化），硬件使用执行掩码来控制哪些线程实际执行当前的指令。例如，先执行`if`路径，此时走向`else`路径的线程被掩码（禁用）；然后执行`else`路径，此时走向`if`路径的线程被掩码。这会导致串行化执行不同的分支路径，降低了Warp的有效计算效率。
- **独立线程调度（Independent Thread Scheduling）**：从Volta架构开始，NVIDIA引入了更灵活的线程调度机制。虽然Warp仍然是基本的调度单位，但在某些情况下（如分支分化后），线程可以在Warp内以更独立的方式重新汇合或管理程序计数器，这有助于在某些复杂控制流场景下提高效率，但SIMT的基本原则依然存在。

指令流水线：

GPU的执行单元也采用流水线技术来提高指令吞吐量。一条指令的执行通常分为多个阶段，如：

1. 指令获取 (Fetch)
2. 指令解码 (Decode)
3. 操作数读取 (Operand Read)
4. 执行 (Execute)
5. 写回结果 (Write-back) 流水线深度和具体阶段因GPU架构而异。

### 7. GPU内存层次结构：导览

GPU拥有一个复杂的内存层次结构，了解各类内存的特性、访问速度和作用域对于编写高性能CUDA程序至关重要。内存层次结构从最快但最小的寄存器到最大但最慢的全局内存。

_(NVIDIA官方文档中经典的内存层次结构图，建议参考)_

#### 寄存器（Registers）

- **特性**：寄存器是GPU上**最快**的内存，位于SM内部。
- **作用域**：每个线程拥有自己的一组私有寄存器。一个线程的寄存器对其他线程不可见。
- **生命周期**：与线程的生命周期相同。
- **访问延迟**：极低，通常0-1个时钟周期（如果操作数已在寄存器中）。
- **容量**：每个SM拥有一个寄存器文件（例如64K个32位寄存器或更多），由该SM上活动的所有线程共享。每个线程可使用的寄存器数量是有限制的（例如，每个线程最多255个，具体取决于计算能力）。
- **使用**：编译器会自动将内核函数中的大部分标量变量（未被`volatile`修饰或数组形式的局部变量）分配到寄存器中。如果内核使用的寄存器过多（称为“寄存器压力”），可能会限制SM上可以同时活动的线程块数量（即降低占用率），因为SM的总寄存器数量是固定的。开发者可以通过编译选项（如`-maxrregcount`）或`__launch_bounds__`来控制每个线程的最大寄存器使用量。
- **溢出**：当内核需要的寄存器数量超过硬件限制，或者编译器策略决定将某些变量移出寄存器时，这些变量会被“溢出”到**局部内存（Local Memory）**。局部内存虽然在逻辑上是线程私有的，但物理上通常位于全局内存中，因此访问速度远慢于寄存器。

#### 共享内存（Shared Memory）

- **特性**：共享内存是位于SM芯片上的一块高速读写内存，其访问速度远快于全局内存，接近寄存器的访问速度（如果无bank冲突）。
- **作用域**：每个线程块（Block/CTA）拥有一块私有的共享内存。块内的所有线程都可以访问该块的共享内存。不同线程块之间的共享内存是隔离的。
- **生命周期**：与线程块的生命周期相同。当线程块执行完毕，其共享内存中的数据也随之失效。
- **访问延迟**：较低，通常几十个时钟周期（无bank冲突时）。
- **容量**：每个SM的共享内存容量是有限的（例如，Volta/Turing/Ampere架构通常每个SM可配置高达48KB、64KB或96KB，部分数据中心卡如A100可达164KB，与L1缓存共享物理空间，可按需分配比例）。一个线程块可以使用的共享内存量也有限制。
- **使用**：开发者需要使用 `__shared__` 关键字在内核函数中显式声明共享内存变量。它对于线程块内的线程协作至关重要，常用于：
    - 缓存从全局内存中读取的数据，以供块内线程多次重用。
    - 实现高效的并行算法，如规约（reduction）、扫描（scan）、矩阵转置等。
    - 作为线程间交换中间结果的暂存区。
- **Bank冲突（Bank Conflict）**：共享内存被组织成多个等大小的内存模块，称为bank（通常是32个，对应Warp的大小）。如果一个Warp中的多个线程同时访问同一个bank中的不同地址（或某些特定模式下的相同地址），就会发生bank冲突，导致访问被串行化，从而降低共享内存的访问带宽。优化共享内存访问模式以避免bank冲突是性能调优的关键点。

#### L1缓存（L1 Cache）与纹理缓存（Texture Cache）

- **L1缓存**：
    - **特性**：每个SM内部都有一个L1数据缓存。在现代NVIDIA GPU中，L1缓存通常与共享内存在同一块物理SRAM上，其大小可以根据内核的需求进行配置（例如，优先分配给L1缓存还是共享内存）。
    - **作用域**：L1缓存对于单个SM是私有的。
    - **功能**：主要用于缓存对**局部内存（Local Memory）**和**全局内存（Global Memory）**的访问。当线程访问这些内存时，数据可能会被加载到L1缓存中，后续对相同数据的访问如果命中L1缓存，则速度会快很多。
    - **访问延迟**：比访问全局内存快得多，但慢于寄存器和共享内存（如果命中，几十个时钟周期）。
- **纹理缓存（Texture Cache）**：
    - **特性**：每个SM还拥有专门为纹理内存访问优化的只读缓存。
    - **功能**：纹理内存和纹理缓存设计用于图形渲染中的纹理采样，具有空间局部性优化、硬件插值、边界模式处理等特性。在通用计算中，当内存访问模式具有良好的空间局部性（尤其是2D）时，使用纹理内存（通过纹理对象或绑定纹理）可以利用纹理缓存获得性能优势。

#### L2缓存（L2 Cache）

- **特性**：L2缓存是位于GPU芯片上，被**所有SM共享**的一级缓存。
- **作用域**：对整个GPU设备可见。
- **功能**：作为全局内存访问的下一级缓存。当L1缓存未命中时，会尝试从L2缓存获取数据。L2缓存的命中也能显著减少对慢速全局内存的直接访问。它是连接SM和设备内存（全局内存）的重要桥梁。
- **容量**：比L1缓存大得多，通常为几MB到几十MB（例如，消费级GPU可能有4-6MB，数据中心GPU如A100有40MB，H100有50MB）。
- **访问延迟**：慢于L1缓存，但仍远快于全局内存（约200个时钟周期）。

#### 全局内存（Global Memory / Device Memory）

- **特性**：全局内存是GPU上**最大**的内存空间，但也是访问延迟**最高**的。它通常指GPU板载的DRAM（如GDDR6, HBM2/HBM3）。
- **作用域**：所有SM上的所有线程都可以访问全局内存。CPU（主机）也可以通过CUDA API（如 `cudaMemcpy`）与GPU的全局内存进行数据传输。
- **生命周期**：在CUDA上下文中分配的全局内存，其生命周期可以跨越多个内核函数的调用，直到被显式释放（如 `cudaFree`）或CUDA上下文销毁。
- **容量**：通常为几GB到几十GB，甚至更多（例如，消费级GPU有8GB-24GB，专业卡和数据中心GPU可达48GB, 80GB, 甚至更高）。
- **访问延迟**：非常高，可能需要400-800个时钟周期。
- **带宽**：尽管延迟高，但现代GPU的全局内存带宽非常大（数百GB/s到几TB/s），通过大规模并行访问和合并访问来摊销延迟，实现高吞吐量。
- **使用**：
    - 在主机端使用 `cudaMalloc()` 分配，使用 `cudaMemcpy()` 进行数据传输。
    - 在内核中直接通过指针访问。
- **合并访问（Coalesced Access）**：当一个Warp中的32个线程访问全局内存时，如果它们访问的内存地址是连续的、对齐的，并且符合特定模式（例如，32个线程访问一个连续的128字节块），这些访问可以被硬件合并成一次或少数几次内存事务。合并访问是最大化全局内存带宽利用率和性能的关键。非合并的、随机的访问会导致大量独立的内存事务，严重降低性能。

#### 常量内存（Constant Memory）

- **特性**：常量内存是一块专用的、**只读**的内存空间，位于设备内存中，但有专门的片上**常量缓存（Constant Cache）**。
- **作用域**：对所有线程可见。
- **生命周期**：数据在主机端定义（使用 `__constant__` 关键字声明全局范围的变量），并通过 `cudaMemcpyToSymbol()` 从主机复制到设备的常量内存空间。其内容在内核执行期间保持不变。
- **容量**：通常较小，例如每个设备64KB。
- **使用**：当一个Warp中的所有线程都从相同的内存地址读取数据时，常量内存非常高效。这是因为数据可以从常量缓存中广播给Warp中的所有线程，只需要一次读取操作。适用于存储内核执行期间不变的配置参数、查找表等。

#### 纹理内存（Texture Memory） (概念重申，与缓存关联)

- **特性**：纹理内存不是一种独立的物理内存类型，而是通过纹理引用（Texture Reference）或纹理对象（Texture Object）来访问设备内存（通常是全局内存）的一种特殊方式。它利用了SM内部的专用**纹理缓存**。
- **功能**：
    - **缓存优化**：纹理缓存针对2D（甚至1D、3D）空间局部性进行了优化。这意味着如果线程访问邻近的纹理元素，命中缓存的概率很高。
    - **硬件特性**：支持硬件级别的数据类型转换、地址计算（例如，归一化坐标）、边界处理（如钳位、环绕）和滤波（如线性插值）。
- **使用**：特别适用于图像处理、信号处理等领域，其中内存访问模式具有空间局部性，或者需要硬件插值等功能。通过将全局内存数据绑定到纹理，可以利用这些硬件特性来简化代码并可能提高性能。
