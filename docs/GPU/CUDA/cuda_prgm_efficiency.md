# CUDA并行计算模式与优化策略

## 1. 编写高效的CUDA程序

### 1.1 理解资源限制与最大化占用率（Occupancy）

#### 资源限制

每个SM（Streaming Multiprocessor）拥有的硬件资源是有限的。当线程块被调度到SM上执行时，它们会消耗这些资源。主要的资源限制包括：

- **每个SM的最大线程数**：一个SM能够同时容纳的总线程数是有限的（例如，Kepler为2048，Pascal/Volta/Turing/Ampere/Ada通常为1024或1536，具体取决于GPU型号和计算能力）。
- **每个SM的最大线程块数**：一个SM能够同时驻留的线程块数量也是有限的（例如，Kepler为16，Pascal及以后架构通常为16到32个，具体取决于资源使用）。
- **每个SM的寄存器文件大小**：SM内所有活动线程共享一个总的寄存器池（例如，64K个32位寄存器，即256KB）。如果每个线程使用较多寄存器，那么SM能容纳的线程总数就会减少。
- **每个SM的共享内存大小**：SM内所有活动线程块共享一个总的共享内存池（例如，48KB、64KB、96KB、128KB、164KB，可配置）。如果每个线程块使用较多共享内存，那么SM能容纳的线程块总数就会减少。
- **每个SM的最大线程束槽位（Warp Slots）**：一个SM可以并发管理和调度的Warp数量是有限的（例如，通常是64个Warp，即64 * 32 = 2048个线程，但这并不意味着所有这些Warp都能同时处于"执行"状态，而是"活跃"状态，可以被调度器选择）。

如何计算SM上可并发的线程块数量：

一个SM能同时执行的线程块数量（也称为"活跃线程块数"）受到上述所有资源限制的制约。它取决于以下几个因素的最小值：

1. 基于每个SM最大线程块数的硬性限制。
2. 基于每个SM最大线程数的限制：`SM最大线程数 / 每块线程数`。
3. 基于每个SM总寄存器数的限制：`SM总寄存器数 / (每块线程数 * 每线程平均使用寄存器数)`。
4. 基于每个SM总共享内存的限制：`SM总共享内存 / 每块使用共享内存大小`。

取这些计算结果中的最小值，就是单个SM上可以同时运行的最大线程块数量。

#### 占用率（Occupancy）优化

占用率定义：

SM的占用率（Occupancy）是指SM上实际活跃的Warp数量与SM硬件能够支持的最大活跃Warp数量的比值。通常以百分比表示。

例如，如果一个SM最多支持64个活跃Warp，而当前内核配置和资源使用使得每个SM上实际有32个活跃Warp，则占用率为50%。

占用率为何重要：

较高的占用率意味着SM上有更多的Warp可供线程束调度器选择。这对于隐藏内存延迟和其他长延迟指令的延迟至关重要。当一个Warp因为等待数据而暂停时，如果SM上有许多其他活跃且就绪的Warp，调度器可以迅速切换到它们，保持计算单元繁忙。如果占用率过低，SM上可供切换的Warp数量不足，计算单元可能会因为等待而空闲，从而降低GPU的整体吞吐量。

**影响占用率的因素**：

- **每线程块的线程数 (Threads per Block)**：直接影响每个块产生的Warp数量。
- **每线程使用的寄存器数 (Registers per Thread)**：使用的寄存器越多，SM能容纳的总线程数就越少。
- **每线程块使用的共享内存大小 (Shared Memory per Block)**：使用的共享内存越多，SM能容纳的线程块数就越少，进而可能影响总活跃Warp数。

**增加（或优化）占用率的方法**：

- **调整线程块大小**：选择合适的线程块大小（通常是Warp大小32的倍数，如128、256、512个线程/块）可以在满足其他资源约束的前提下产生足够的Warp。
- **减少每线程寄存器使用量**：
  - 编写更简洁的代码。
  - 使用编译选项（如 `-maxrregcount`）限制编译器分配的寄存器数量（但这可能导致寄存器溢出到局部内存，需要权衡）。
  - 使用 `__launch_bounds__(maxThreadsPerBlock, minBlocksPerMultiprocessor)` 内核启动边界限定符，向编译器提供关于内核启动配置的提示，帮助其优化寄存器分配。
- **减少每线程块共享内存使用量**：如果共享内存是瓶颈，考虑优化数据结构或算法以减少其需求。
- **权衡**：需要注意的是，**100%的占用率并不总是能带来最佳性能**。有时，即使占用率稍低，但如果每个线程能做更多有用的工作（例如，由于有更多可用寄存器而避免了局部内存访问，或者指令级并行度更高），整体性能也可能更好。占用率是实现延迟隐藏的重要手段，但并非唯一目标。

使用占用率计算器：

NVIDIA CUDA工具包中通常包含一个占用率计算器（Excel电子表格或集成在Nsight Compute等分析工具中）。开发者可以输入目标GPU架构、内核的线程块大小、每线程寄存器使用量和每块共享内存使用量，该工具会计算出理论占用率，并指出是哪种资源首先成为限制因素。这有助于指导优化方向。

### 1.2 CUDA中常见的并行计算模式

CUDA程序设计通常围绕一些经典的并行计算模式展开。理解这些模式有助于将问题分解并有效地映射到GPU架构上。

#### 映射（Map）

这是最简单也是最常见的并行模式，也称为"易并行"（Embarrassingly Parallel）。

- **核心思想**：将一个操作独立地应用于输入数据集中的每个元素，生成输出数据集中的对应元素。每个元素的计算与其他元素的计算完全无关，不需要线程间的通信或同步。
- **CUDA实现**：通常每个线程负责处理输入数据的一个或多个元素，并将结果写入输出数组的相应位置。
- **示例**：向量加法（`C[i] = A[i] + B[i]`）、图像亮度调整、对每个数据点应用一个数学函数等。

#### 规约（Reduction）

规约操作是将一个输入数据集通过一个二元结合操作（如求和、求积、找最大/最小值、逻辑与/或）合并成一个单一的值或一个更小的数据集。

- **核心思想**：并行地将数据分成小块，在块内进行部分规约，然后将各块的部分规约结果进一步合并，直到得到最终结果。
- **CUDA实现**：通常涉及多个阶段。
    1. **块内规约**：每个线程块内的线程协作，使用共享内存高效地对其负责的数据子集进行规约。这通常采用树形归约的策略（例如，相邻线程两两相加，然后结果再两两相加，直到块内只剩一个结果）。需要 `__syncthreads()` 进行同步。
    2. **块间规约**：将每个线程块产生的部分结果（通常写回全局内存）进一步规约。这可以通过启动第二个内核（如果部分结果数量仍较大），或者由CPU完成最后的合并。
- **示例**：计算数组中所有元素的总和、找到数组中的最大值、计算点积等。

#### 扫描（Scan / Prefix Sum）

扫描操作（也称前缀和）对于输入数组中的每个元素，计算其前面所有元素（包括自身）通过某个二元操作符累积的结果。有两种主要类型：包含式扫描（inclusive scan）和排除式扫描（exclusive scan）。

- **核心思想**：这是一个比规约更复杂的并行模式，因为每个输出都依赖于其前面的多个输入。高效的并行扫描算法通常基于分治策略，如Blelloch算法或Hillis-Steele算法。
- **CUDA实现**：通常也涉及块内操作（使用共享内存和多次同步）和块间操作（如果数据量非常大）。
- **示例**：计算数组的前缀和（`output[i] = input[0] + ... + input[i]`）、构建某些数据结构（如基数排序中的偏移量计算）、解决资源分配问题等。

#### 直方图（Histogram）

直方图操作是统计数据集中每个值（或每个值范围/bin）出现的频率。

- **核心思想**：对于输入数据集中的每个元素，确定它属于哪个bin，然后增加该bin的计数器。主要的挑战在于多个线程可能同时尝试更新同一个bin的计数器，这需要原子操作来保证正确性。
- **CUDA实现**：
  - **全局原子操作**：每个线程计算其数据元素对应的bin，然后使用全局内存上的原子加法（`atomicAdd()`）来更新该bin的计数器。这种方法简单，但如果冲突很多，原子操作的串行化会影响性能。
  - **共享内存私有化/部分直方图**：每个线程块计算其负责数据子集的私有直方图（存储在共享内存中，使用共享内存上的原子操作或无冲突的更新策略）。完成后，将这些部分直方图合并到全局直方图中（可能需要额外的内核或原子操作）。
  - **排序后计算**：先对数据进行排序，然后相同值的元素会聚集在一起，可以更容易地并行计算频率。
- **示例**：图像处理中的灰度直方图、数据分析中的特征分布统计等。

#### 模板运算（Stencil / Neighborhood Computation）

模板运算中，输出数据集中每个元素的值是根据其输入数据集中对应位置及其邻近元素（形成一个"模板"或"窗口"）计算得到的。

- **核心思想**：每个输出点的计算依赖于输入数据的一个局部区域。
- **CUDA实现**：
  - **数据共享**：为了高效计算，通常会将输入数据的一个 tile 加载到共享内存中，这个tile需要包含计算输出tile所需的所有邻域数据（包括"幽灵单元"或"光环区域"）。
  - **边界处理**：需要仔细处理位于输入数据边界的元素，因为它们的邻域可能不完整。
- **示例**：图像卷积（如模糊、锐化）、有限差分法解偏微分方程、细胞自动机等。

### 1.3 基础优化策略

编写高性能CUDA程序不仅仅是实现并行算法，还需要细致的优化。以下是一些基础且重要的优化策略：

#### 内存访问优化

由于全局内存访问延迟很高，优化内存访问是CUDA性能调优的核心。

- **最大化合并访问（Maximize Coalesced Access）**：
  - 确保同一Warp中的线程访问连续且对齐的全局内存地址。例如，如果`threadIdx.x`在Warp内从0到31变化，那么访问`data[base + threadIdx.x]`通常是合并的（假设`data`是对齐的，并且元素大小合适）。
  - 如果数据结构是二维的（如矩阵），确保线程索引的映射方式能够产生合并访问。例如，对于行主序存储的矩阵，让Warp内的线程访问同一行的连续元素。
- **高效使用共享内存（Effective Use of Shared Memory）**：
  - **数据重用**：将从全局内存中读取的数据缓存在共享内存中，供线程块内的线程多次访问，从而避免重复的高延迟全局内存读取。
  - **优化访问模式**：设计共享内存中的数据布局和访问模式，以避免或减少bank冲突。
  - **减少全局内存流量**：通过在共享内存中进行中间计算（如部分规约），可以减少写入全局内存的数据量。
- **最小化全局内存流量**：
  - 只加载和存储绝对必要的数据。
  - 如果可能，在GPU上直接生成数据，而不是从CPU传输。
  - 使用更小的数据类型（例如，如果精度允许，使用`float`代替`double`，或使用`short`代替`int`），但这需要仔细评估对结果精度的影响。
- **利用L1/L2缓存**：虽然对缓存的直接控制有限，但具有良好空间和时间局部性的访问模式更有可能从缓存中受益。
- **考虑使用纹理内存/常量内存**：对于只读数据且具有特定访问模式（如空间局部性或Warp内统一访问），可以利用纹理缓存或常量缓存。

#### 执行优化

- **避免线程束分化（Avoid Warp Divergence）**：
  - 尽量使Warp内的线程执行相同的代码路径。如果必须使用条件分支，尝试使分支条件对于整个Warp（或尽可能多的线程）是一致的。
  - 如果分支内的计算量很小，有时即使有分化，其开销也可能小于其他更复杂的避免分化的策略。
- **指令级考量**：
  - **整数运算 vs. 浮点运算**：整数运算通常比浮点运算快。
  - **单精度 vs. 双精度**：单精度（`float`）运算通常比双精度（`double`）运算快得多，并且消耗更少的内存带宽和寄存器。仅在确实需要高精度时才使用双精度。现代GPU对FP16/BF16/TF32等混合精度的支持也为AI等领域提供了更多优化选项。
  - **特殊函数单元（SFU）**：`sinf()`, `cosf()`, `logf()`, `expf()`, `rsqrtf()` 等函数由SFU执行，它们通常比一系列基本算术指令（如果能实现相同功能的话）更快，但其吞吐量低于简单加法或乘法。使用`__fdividef(x, y)`通常比 `x / y`更快（对于单精度浮点除法）。
  - **乘加运算（Fused Multiply-Add, FMA）**：`fmaf(a, b, c)` 计算 `a*b + c`，通常比单独的乘法和加法更快，且只进行一次舍入，精度可能更高。编译器通常会自动生成FMA指令。
- **循环展开（Loop Unrolling）**：在某些情况下，手动展开小的、固定迭代次数的循环（或使用 `#pragma unroll` 指示编译器）可以减少循环控制开销并增加指令级并行性，但可能会增加寄存器压力和代码大小。
- **减少不必要的同步**：`__syncthreads()` 是一个开销较大的操作，因为它会暂停线程块的执行，直到所有线程都到达同步点。仅在确实需要保证块内所有线程对共享内存的读写顺序或协同工作时才使用。

#### 占用率与其他因素的权衡

- 如前所述，高占用率有助于隐藏延迟，但并非唯一目标。有时为了获得更高的指令级并行（ILP）或减少对局部内存的访问（通过允许使用更多寄存器），牺牲一定的占用率可能反而带来更好的整体性能。
- **任务粒度**：每个线程做太少的工作（细粒度）可能导致启动开销和同步开销占比较大。每个线程做太多工作（粗粒度）可能导致并行度不足或负载不均。需要找到合适的平衡点。

#### 使用CUDA分析工具

NVIDIA提供了强大的性能分析工具，如 **NVIDIA Nsight Systems** (用于系统级性能分析，包括CPU/GPU交互和API调用) 和 **NVIDIA Nsight Compute** (用于CUDA内核的详细性能分析和瓶颈定位)。这些工具可以帮助开发者：

- 识别性能瓶颈（是内存带宽限制、计算能力限制还是延迟问题？）。
- 查看占用率、指令吞吐量、内存访问模式、缓存命中率、分支分化等关键指标。
- 获取具体的优化建议。 定期使用分析工具来指导优化工作是至关重要的。
